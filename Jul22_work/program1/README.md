## Recursive

Pseudocode
1.	ถ้าสตริงว่างอยู่แล้ว ให้คืนค่าสตริงว่างกลับไปทันที (จบการทำงาน)
2.	ถ้ายังไม่ว่าง ให้เรียกเมธอดตัวเองซ้ำ โดยส่งสตริงที่ตัดตัวอักษรตัวแรกออกไปแล้ว
3.	นำผลลัพธ์ที่ได้จากข้อ 2 มาต่อท้ายด้วยตัวอักษรตัวแรกที่ตัดออกไปก่อนหน้านี้
4.	คืนค่าผลลัพธ์ที่ได้

แนวคิด
นำตัวอักษรตัวสุดท้ายของสตริงมาต่อกับผลลัพธ์ที่ได้จากการเรียกเมธอดแบบเวียนเกิดกับสตริงส่วนที่เหลือ (ตัดตัวสุดท้ายออก) จนกระทั่งสตริงว่าง (Base Case)

ข้อดี
- โค้ดสั้น อ่านง่าย
- เหมาะสำหรับศึกษาแนวคิดการเวียนเกิด (Recursion)
- โครงสร้างสอดคล้องกับนิยามของการกลับสตริง

ข้อจำกัด
- Time Complexity = O(n²)
- Space Complexity = O(n²)
- มี Call Stack จำนวนมาก
- มีการสร้าง String ใหม่ทุกครั้งจากการใช้ `substring()` และ `+`
- เสี่ยงเกิด StackOverflowError เมื่อสตริงมีขนาดใหญ่มาก

## Iterative

Pseudocode
1.	สร้างตัวแปรเก็บผลลัพธ์ว่างๆ ไว้ก่อน (StringBuilder)
2.	เริ่มอ่านตัวอักษรจากตำแหน่งสุดท้ายของสตริง ไล่ย้อนไปทีละตำแหน่งจนถึงตัวแรก
3.	ทุกครั้งที่อ่านตัวอักษรได้ ให้นำไปต่อท้ายตัวแปรผลลัพธ์
4.	เมื่ออ่านครบทุกตัวแล้ว คืนค่าตัวแปรผลลัพธ์ออกไปเป็นสตริง

แนวคิด: ใช้ลูปอ่านตัวอักษรจากตำแหน่งสุดท้ายไล่ย้อนไปยังตำแหน่งแรก แล้วต่อเข้ากับ StringBuilder

ข้อดี
- Time Complexity = O(n)
- Space Complexity = O(n)
- ทำงานเร็วกว่า Recursive มาก
- ใช้ StringBuilder ลดการสร้าง Object ซ้ำ
- ไม่มีปัญหา Stack Overflow
- เหมาะกับข้อมูลขนาดใหญ่

ข้อจำกัด
- โค้ดยาวกว่า Recursive เล็กน้อย
- ไม่ได้แสดงแนวคิดของ Recursion

## วิเคราะห์

## จำนวนครั้งที่แต่ละอัลกอริทึมประมวลผลตัวอักษร
ทั้งสองวิธีอ่าน/ประมวลผลตัวอักษรครบ n ตัวเท่ากัน แต่ Recursive มีต้นทุนแฝงเพิ่มในแต่ละครั้ง เพราะต้องสร้างสตริงย่อยด้วย substring() ทุกรอบ ส่วน Iterative แต่ละรอบมีต้นทุนคงที่

## Time Complexity
Recursive คือ O(n²) เพราะ substring() และการต่อสตริงด้วย + แต่ละครั้งใช้เวลา O(n) และถูกเรียกซ้ำ n ครั้ง ส่วน Iterative คือ O(n) เพราะ append ของ StringBuilder ใช้เวลาคงที่ต่อครั้ง

## Space Complexity
Recursive ใช้ O(n²) เพราะมีทั้ง Call Stack ลึก n ระดับ และสร้างสตริงใหม่ซ้ำในแต่ละระดับ ส่วน Iterative ใช้ O(n) เพราะสร้างผลลัพธ์เพียงชุดเดียว

## ผลจากการต่อสตริงด้วยเครื่องหมาย +
ทำให้ Recursive ช้าลงมาก เพราะ String เป็น immutable ทุกครั้งที่ + จะต้องสร้างอ็อบเจกต์ String ใหม่ทั้งหมดขึ้นมาแทนที่ ยิ่งสตริงยาว ยิ่งเสียเวลาคัดลอกข้อมูลซ้ำหลายรอบ

## ความแตกต่างระหว่าง String และ StringBuilder
StringBuilder ใช้ buffer ภายในที่ขยายขนาดได้เอง และเพิ่มตัวอักษรแต่ละตัวด้วยเวลาคงที่แบบ amortized O(1) จึงไม่มีปัญหาการสร้างอ็อบเจกต์ใหม่ซ้ำ ๆ เหมือน String

## ผลเมื่อทดสอบกับสตริงขนาด 10, 100, 1,000 และ 10,000 ตัวอักษร
เมื่อ n เพิ่มขึ้น 10 เท่า เวลาของ Recursive จะเพิ่มขึ้นประมาณ 100 เท่า (ตาม O(n²)) ในขณะที่ Iterative จะเพิ่มขึ้นประมาณ 10 เท่าเท่านั้น (ตาม O(n)) ความแตกต่างจะยิ่งชัดเจนเมื่อ n มีขนาดใหญ่ขึ้น

## สรุป
Iterative เหมาะสมกว่าในทุกกรณีที่เน้นประสิทธิภาพ โดยเฉพาะสตริงขนาดใหญ่ ส่วน Recursive เหมาะสำหรับกรณีที่ต้องการสาธิตแนวคิดการเวียนเกิด หรือสตริงมีขนาดเล็กมากซึ่งความแตกต่างของเวลาไม่มีนัยสำคัญ
