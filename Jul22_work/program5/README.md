## Recursive Partition

Pseudocode
1.	ตั้งตัวชี้ left ไว้ที่ต้นอาร์เรย์ และตัวชี้ right ไว้ที่ท้ายอาร์เรย์
2.	ถ้า left เลื่อนมาเจอหรือเลย right แล้ว ให้หยุดทำงาน
3.	ถ้าตัวเลขที่ตำแหน่ง left มีค่าน้อยกว่าหรือเท่ากับ k อยู่แล้ว ให้เลื่อน left ไปทางขวา 1 ตำแหน่ง แล้วเรียกเมธอดตัวเองซ้ำ
4.	ถ้าไม่ใช่ข้อ 3 แต่ตัวเลขที่ตำแหน่ง right มีค่ามากกว่า k อยู่แล้ว ให้เลื่อน right มาทางซ้าย 1 ตำแหน่ง แล้วเรียกเมธอดตัวเองซ้ำ
5.	ถ้าไม่เข้ากรณีไหนเลย ให้สลับค่าทั้งสองตำแหน่งกัน แล้วเลื่อนตัวชี้ทั้งสองเข้าหากันฝั่งละ 1 ตำแหน่ง จากนั้นเรียกเมธอดตัวเองซ้ำ


## Iterative Partition

Pseudocode
1.	ตั้งตัวชี้ left ไว้ที่ต้นอาร์เรย์ และตัวชี้ right ไว้ที่ท้ายอาร์เรย์
2.	วนทำซ้ำตราบใดที่ left ยังมาไม่ถึง right:
–	ถ้าตัวเลขที่ตำแหน่ง left มีค่า ≤ k อยู่แล้ว ให้เลื่อน left ไปทางขวา 1 ตำแหน่ง
–	ไม่เช่นนั้น ถ้าตัวเลขที่ตำแหน่ง right มีค่า > k อยู่แล้ว ให้เลื่อน right มาทางซ้าย 1 ตำแหน่ง
–	ไม่เช่นนั้น ให้สลับค่าทั้งสองตำแหน่ง แล้วเลื่อนตัวชี้ทั้งสองเข้าหากันฝั่งละ 1 ตำแหน่ง
3.	เมื่อ left มาถึง right แล้ว ให้หยุดทำงาน

## Sorting-Based Algorithm

Pseudocode
1.	เรียงลำดับอาร์เรย์จากน้อยไปมาก ด้วยฟังก์ชันเรียงลำดับมาตรฐาน
2.	เนื่องจากเรียงลำดับแล้ว ตัวเลขที่มีค่าน้อยกว่าหรือเท่ากับ k จะอยู่ก่อนตัวเลขที่มากกว่า k โดยอัตโนมัติ (ไม่ต้องทำอะไรเพิ่ม)


# วิเคราะห์

# Time Complexity ของแต่ละวิธี
Recursive Partition และ Iterative Partition ใช้เวลา O(n) เท่ากัน เพราะตัวชี้ทั้งสองเคลื่อนที่เข้าหากันโดยไม่ย้อนกลับ ส่วน Sorting-Based ใช้เวลา O(n log n) เพราะต้องเรียงลำดับอาร์เรย์ทั้งชุดก่อน

# Space Complexity ของแต่ละวิธี
Recursive Partition ใช้ O(n) จาก Call Stack, Iterative Partition ใช้เพียง O(1) เพราะไม่ต้องเก็บอะไรเพิ่ม ส่วน Sorting-Based ใช้ O(log n) จาก recursion ภายในของอัลกอริทึมเรียงลำดับ

# อัลกอริทึมใดทำงานแบบ In-place ได้
ทั้งสามวิธีทำงานแบบ in-place ได้ทั้งหมด คือแก้ไขอาร์เรย์เดิมโดยตรงโดยไม่ต้องสร้างอาร์เรย์ใหม่ (Sorting-Based ก็แก้ไขอาร์เรย์เดิมเช่นกัน เพียงแต่ใช้พื้นที่เพิ่มเติมเล็กน้อยภายในกระบวนการเรียงลำดับ)

# เหตุผลที่การเรียงลำดับอาจทำให้โปรแกรมช้ากว่าที่จำเป็น
โจทย์นี้ต้องการเพียงแบ่งกลุ่มสมาชิกเป็นสองฝั่งเท่านั้น ไม่จำเป็นต้องเรียงลำดับภายในแต่ละฝั่ง การเรียงทั้งอาร์เรย์จึงทำงานเกินความจำเป็น (O(n log n) แทนที่จะเป็น O(n))

# ความสัมพันธ์กับ Quick Sort
ขั้นตอน Partition ในข้อนี้เหมือนกับขั้นตอน Partition ของ Quick Sort ทุกประการ เพียงแต่ Quick Sort ใช้ค่า Pivot ที่เลือกจากอาร์เรย์เอง แล้วเรียก Partition ซ้ำ ๆ กับอาร์เรย์ย่อยทั้งสองฝั่งต่อไปเรื่อย ๆ จนเรียงลำดับสมบูรณ์ ในขณะที่โจทย์นี้ใช้ค่า k ที่กำหนดมาแทน pivot และทำ Partition เพียงรอบเดียว

# สรุป
Iterative Partition เหมาะสมที่สุด เพราะให้ Time Complexity O(n) ซึ่งดีที่สุดเท่าที่เป็นไปได้สำหรับปัญหานี้ และใช้พื้นที่เพียง O(1) Recursive Partition ให้ผลลัพธ์เดียวกันแต่มีต้นทุนแฝงจาก Call Stack ส่วน Sorting-Based ควรหลีกเลี่ยงหากต้องการประสิทธิภาพสูงสุด เพราะทำงานเกินความจำเป็นของโจทย์
