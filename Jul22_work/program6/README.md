## Brute Force

Pseudocode
1.	เลือกตัวเลขตัวแรกในอาร์เรย์มาเป็นตัวตั้ง (เรียกว่าตัวที่ i)
2.	เลือกตัวเลขตัวถัดไปทีละตัวที่อยู่หลังตัวที่ i (เรียกว่าตัวที่ j) มาบวกกับตัวที่ i
3.	ถ้าผลบวกเท่ากับ k ให้ตอบว่าพบคู่คำตอบแล้ว (จบการทำงาน)
4.	ถ้ายังไม่พบ ให้เลื่อนไปลองคู่ถัดไปเรื่อยๆ จนครบทุกคู่ที่เป็นไปได้
5.	ถ้าลองครบทุกคู่แล้วยังไม่เจอ ให้ตอบว่าไม่พบคู่คำตอบ

แนวคิด: ตรวจสอบสมาชิกทุกคู่ที่เป็นไปได้ด้วยลูปซ้อนสองชั้น

ข้อดี
- เข้าใจง่าย
- ใช้ได้แม้อาร์เรย์ยังไม่เรียงลำดับ
- ไม่ต้องมีเงื่อนไขเพิ่มเติม

ข้อจำกัด
- Time Complexity = O(n²)
- ช้ามากเมื่อข้อมูลมีขนาดใหญ่

## Recursive Two-Pointer

Pseudocode
1.	ตั้งตัวชี้ left ไว้ที่ต้นอาร์เรย์ และตัวชี้ right ไว้ที่ท้ายอาร์เรย์
2.	ถ้า left เลื่อนมาเจอหรือเลย right แล้ว ให้ตอบว่าไม่พบคู่คำตอบ (จบการทำงาน)
3.	นำตัวเลขที่ตำแหน่ง left มาบวกกับตัวเลขที่ตำแหน่ง right
4.	ถ้าผลบวกเท่ากับ k ให้ตอบว่าพบคู่คำตอบแล้ว
5.	ถ้าผลบวกน้อยกว่า k ให้เลื่อน left ไปทางขวา 1 ตำแหน่ง (เพื่อให้ผลบวกมากขึ้น) แล้วเรียกเมธอดตัวเองซ้ำ
6.	ถ้าผลบวกมากกว่า k ให้เลื่อน right มาทางซ้าย 1 ตำแหน่ง (เพื่อให้ผลบวกน้อยลง) แล้วเรียกเมธอดตัวเองซ้ำ

แนวคิด: กำหนดตัวชี้ left = 0 และ right = n-1 คำนวณผลรวม a[left] + a[right] หากเท่ากับ k พบคำตอบ หากน้อยกว่า k ให้เลื่อน left ขึ้น (เพื่อเพิ่มผลรวม) หากมากกว่า k ให้เลื่อน right ลง (เพื่อลดผลรวม) แล้วเรียกเมธอดแบบเวียนเกิดกับช่วงใหม่

ข้อดี
- Time Complexity = O(n)
- เร็วที่สุดเมื่อข้อมูลเรียงลำดับแล้ว
- จำนวนการเปรียบเทียบน้อย

ข้อจำกัด
- ต้องใช้อาร์เรย์ที่เรียงลำดับแล้ว
- ใช้ Call Stack O(n)
- เสี่ยง Stack Overflow

## Binary Search

Pseudocode
1.	เลือกตัวเลขตัวแรกในอาร์เรย์มาเป็นตัวตั้ง
2.	คำนวณหาค่าที่ต้องการอีกตัวหนึ่ง คือ k ลบด้วยตัวตั้ง
3.	ใช้ Binary Search ค้นหาค่านั้นในส่วนที่เหลือของอาร์เรย์ (อาร์เรย์เรียงลำดับไว้แล้ว จึงค้นหาได้เร็ว)
4.	ถ้าค้นพบ ให้ตอบว่าพบคู่คำตอบแล้ว (จบการทำงาน)
5.	ถ้ายังไม่พบ ให้เลือกตัวเลขตัวถัดไปมาเป็นตัวตั้งแล้วทำซ้ำตั้งแต่ข้อ 2
6.	ถ้าลองครบทุกตัวแล้วยังไม่พบ ให้ตอบว่าไม่พบคู่คำตอบ

แนวคิด: เลือกสมาชิก a[i] ทีละตัว แล้วใช้ Binary Search ค้นหาค่า k - a[i] ในสมาชิกที่เหลือ

ข้อดี
- Time Complexity = O(n log n)
- ใช้พื้นที่ O(1)
- เหมาะกับข้อมูลที่เรียงลำดับแล้ว
- ใช้หลัก Binary Search ซึ่งมีประสิทธิภาพ

ข้อจำกัด
- ช้ากว่า Two-Pointer
- ต้องใช้อาร์เรย์ที่เรียงลำดับแล้ว
- ต้องค้นหาซ้ำหลายรอบ


## วิเคราะห์

## Time Complexity
Brute Force แย่ที่สุดคือ O(n²) เพราะตรวจทุกคู่ที่เป็นไปได้ Recursive Two-Pointer ดีที่สุดคือ O(n) เพราะตัวชี้เคลื่อนที่เข้าหากันโดยไม่ย้อนกลับ ส่วน Binary Search อยู่ตรงกลางคือ O(n log n) เพราะค้นหา n รอบ รอบละ O(log n)

## Space Complexity
Brute Force และ Binary Search ใช้เพียง O(1) เพราะไม่ต้องเก็บข้อมูลเพิ่ม ส่วน Recursive Two-Pointer ใช้ O(n) จาก Call Stack

## ความจำเป็นที่อาร์เรย์ต้องเรียงลำดับ
Brute Force ไม่จำเป็นต้องเรียงลำดับ เพราะตรวจทุกคู่อยู่แล้ว แต่ Recursive Two-Pointer และ Binary Search ต้องอาศัยอาร์เรย์ที่เรียงลำดับแล้วเท่านั้น จึงจะได้ผลลัพธ์ถูกต้อง

## ให้อธิบายว่าเหตุใด Two-Pointer จึงใช้ได้เมื่ออาร์เรย์เรียงลำดับแล้ว และจะเกิดอะไรขึ้นหากนำวิธีนี้ไปใช้กับอาร์เรย์ที่ยังไม่เรียงลำดับ
-Two-Pointer ตัดสินใจเลื่อนตัวชี้จากการเปรียบเทียบผลรวมกับ k โดยอาศัยว่าเลื่อน left ขวาแล้วค่าต้องเพิ่มขึ้น เลื่อน right ซ้ายแล้วค่าต้องลดลงเสมอ ซึ่งจะเป็นจริงก็ต่อเมื่ออาร์เรย์เรียงลำดับแล้วเท่านั้น
-ถ้าใช้กับอาร์เรย์ที่ไม่เรียงลำดับ ทิศทางการเลื่อนตัวชี้จะไม่รับประกันผลรวมอีกต่อไป ทำให้ตัวชี้เลื่อนผ่านคู่คำตอบที่แท้จริงไปโดยไม่ตรวจเจอ และได้ผลลัพธ์ผิดพลาด

## สรุป
เมื่ออาร์เรย์เรียงลำดับแล้วตามที่โจทย์กำหนด Recursive Two-Pointer เป็นวิธีที่มีประสิทธิภาพด้านเวลาดีที่สุด (O(n)) แม้จะเสียพื้นที่ O(n) จาก Call Stack ก็ตาม หากต้องการหลีกเลี่ยงการใช้ Call Stack ควรเปลี่ยนไปเขียนแบบ Iterative Two-Pointer แทน (Time Complexity เท่ากันแต่ Space เป็น O(1)) ส่วน Binary Search เหมาะกับกรณีที่ต้องการค้นหาแบบไม่ใช้ตัวชี้คู่ แต่ประสิทธิภาพด้อยกว่า Two-Pointer เล็กน้อย และ Brute Force ควรใช้เฉพาะเมื่ออาร์เรย์มีขนาดเล็กมากหรือไม่ได้เรียงลำดับเท่านั้น
