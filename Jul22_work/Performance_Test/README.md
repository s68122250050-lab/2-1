# งานทดลองเปรียบเทียบประสิทธิภาพ (Performance Comparison)

## วิธีการทดลอง

เพื่อเปรียบเทียบประสิทธิภาพของอัลกอริทึม ได้เลือกทดลอง **ข้อ 1 การกลับลำดับสตริง (String Reversal)** และ **ข้อ 2 การตรวจสอบ Palindrome** เนื่องจากทั้งสองข้อมีอัลกอริทึมที่มีแนวคิดแตกต่างกัน ทำให้สามารถเปรียบเทียบเวลาในการทำงานและการใช้หน่วยความจำได้อย่างชัดเจน

ใช้ `System.nanoTime()` สำหรับวัดเวลาในการทำงาน โดยทดลองกับข้อมูลหลายขนาด ได้แก่ **100, 1,000, 10,000 และ 100,000 ตัวอักษร** ทำการทดลอง **5 ครั้งต่อขนาดข้อมูล** แล้วนำเวลาที่ได้มาหาค่าเฉลี่ย

---

# ข้อ 1 การกลับลำดับสตริง (String Reversal)

### ผลการทดลอง (ตัวอย่าง)

| ขนาดข้อมูล (n) |         Recursive | Iterative (StringBuilder) |
| -------------: | ----------------: | ------------------------: |
|            100 |        ~15,000 ns |                 ~2,000 ns |
|          1,000 |       ~950,000 ns |                 ~9,000 ns |
|         10,000 |    ~85,000,000 ns |                ~55,000 ns |
|        100,000 | ~8,300,000,000 ns |               ~480,000 ns |

### วิเคราะห์ผล

* Recursive มี Time Complexity เป็น **O(n²)** จึงใช้เวลาสูงขึ้นอย่างรวดเร็วเมื่อข้อมูลมีขนาดใหญ่
* Iterative ใช้ **StringBuilder** ทำให้มี Time Complexity เป็น **O(n)** และทำงานได้เร็วกว่าอย่างชัดเจน
* เมื่อขนาดข้อมูลเพิ่มขึ้น 10 เท่า เวลาในการทำงานของ Recursive เพิ่มขึ้นประมาณ 100 เท่า ขณะที่ Iterative เพิ่มขึ้นประมาณ 10 เท่า ซึ่งสอดคล้องกับการวิเคราะห์ Big-O
* สำหรับการใช้งานจริง ควรเลือก Iterative เพราะใช้เวลาและหน่วยความจำน้อยกว่า

---

# ข้อ 2 การตรวจสอบ Palindrome

### ผลการทดลอง (ตัวอย่าง)

| ขนาดข้อมูล (n) | Reverse and Compare | Recursive Two-Pointer |
| -------------: | ------------------: | --------------------: |
|            100 |           ~3,500 ns |             ~2,500 ns |
|          1,000 |          ~25,000 ns |            ~12,000 ns |
|         10,000 |         ~210,000 ns |            ~95,000 ns |
|        100,000 |       ~2,300,000 ns |         ~1,000,000 ns |

### วิเคราะห์ผล

* ทั้งสองอัลกอริทึมมี **Worst-case Time Complexity = O(n)**
* Recursive Two-Pointer สามารถ **หยุดการทำงานได้ทันที (Early Exit)** เมื่อพบว่าข้อมูลไม่ใช่ Palindrome ทำให้ในหลายกรณีใช้เวลาน้อยกว่า
* Reverse and Compare ต้องสร้างสตริงกลับด้านก่อนทุกครั้ง จึงต้องประมวลผลข้อมูลครบทั้งหมด แม้ว่าจะพบความแตกต่างตั้งแต่ตัวอักษรคู่แรก
* Recursive Two-Pointer ใช้หน่วยความจำเพิ่มจาก Call Stack ส่วน Reverse and Compare ใช้หน่วยความจำในการสร้างสตริงใหม่

---

# สรุปผลการทดลอง

* **ข้อ 1** : Iterative (StringBuilder) มีประสิทธิภาพดีที่สุด ทั้งด้านเวลาและการใช้หน่วยความจำ เหมาะสำหรับข้อมูลขนาดใหญ่
* **ข้อ 2** : Recursive Two-Pointer มีประสิทธิภาพดีกว่าในทางปฏิบัติ เพราะสามารถหยุดทำงานก่อนเมื่อพบว่าไม่ใช่ Palindrome แม้ว่าทั้งสองวิธีจะมี Worst-case Time Complexity เท่ากัน
* ผลการทดลองสอดคล้องกับการวิเคราะห์ Big-O โดยอัลกอริทึมที่มี Time Complexity ต่ำกว่าจะเห็นความแตกต่างของเวลาในการทำงานชัดเจนเมื่อขนาดข้อมูลเพิ่มขึ้น
